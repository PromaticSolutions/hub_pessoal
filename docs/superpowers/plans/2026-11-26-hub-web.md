# Personal Task Hub Web — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transformar o app desktop v2 em site (Vercel + Supabase) com as mesmas telas, regras e métodos, login único, arquivos no Storage e importação conferida dos dados atuais.

**Architecture:** `src/main` vira `src/server` (sem Electron). Serviços ficam com os mesmos nomes e parâmetros, mas `async`, sobre uma interface `Db` (postgres.js em produção, PGlite em testes/dev). A API continua sendo o mapa `handlers` (mesmos 128 métodos), servido por `POST /api/rpc` numa função Vercel; o renderer troca IPC por `fetch` com JWT do Supabase.

**Tech Stack:** a da v2 sem Electron/better-sqlite3 em runtime + `postgres` (postgres.js), `@electric-sql/pglite` (dev/test), `@supabase/supabase-js`, `esbuild` (empacotar funções), Vite 8 SPA, Vitest 4 (Node puro), Playwright (Chromium).

**Spec:** `docs/superpowers/specs/2026-11-26-hub-web-design.md` (§N = seção do spec). Specs v1/v2 continuam valendo para regras de negócio.

## Global Constraints

- Nomes, entradas (zod) e saídas de todos os métodos de `handlers.ts` não mudam, exceto os listados na Task 6 (métodos de sistema/arquivo/backup do Electron).
- Todo serviço exportado mantém nome e parâmetros; passa a retornar `Promise`. Todo teste unitário existente continua com as mesmas asserções (só ganha `await`/`async`).
- `data-testid` existentes preservados. UI em pt-BR.
- Datas continuam texto ISO nas colunas; booleanos inteiros 0/1; `position` `double precision`; ids `integer generated by default as identity`.
- Ordenação: SQLite põe NULL primeiro em ASC. Em todo `ORDER BY` sobre coluna anulável, escrever `NULLS FIRST` (ASC) / `NULLS LAST` (DESC) para manter a ordem atual. `LIKE` do SQLite ignora maiúsculas → usar `ILIKE`.
- Dentro de transação, **toda** consulta usa o `ctx` da transação (`withTx`). Consulta no `ctx` externo dentro de `tx` = bug (no PGlite trava e o teste estoura o tempo).
- Fuso: servidor e testes rodam com `process.env.TZ = process.env.APP_TZ ?? 'America/Sao_Paulo'`, definido antes de qualquer import que calcule datas.
- Produção nunca carrega PGlite, Storage local nem bypass de login; `createProdContext` lança erro se `HUB_DEV_AUTH` estiver ligado ou faltar `DATABASE_URL`/`SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY`/`ALLOWED_EMAIL`.
- Segredos só em `.env.local` (ignorado) e nas variáveis da Vercel; nunca em código, teste ou log.
- Bucket do Storage: `hub-files` (privado). Prefixos: `attachments/`, `logos/`, `deleted/`, `backups/auto/`, `backups/manual/`, `uploads/tmp/`. URLs assinadas valem 3600 s. Tamanho máximo de arquivo: 50 MB.
- Conexão: API usa `DATABASE_URL` (pooler 6543, `prepare: false`, `max: 1`); migração/importação usam `DATABASE_URL_SESSION` (5432).
